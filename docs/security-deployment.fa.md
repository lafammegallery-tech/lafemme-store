# انتشار اصلاحات امنیتی

این نسخه فقط کارت‌به‌کارت را می‌پذیرد. پیش از انتشار، از دیتابیس و volume آپلود پشتیبان بگیرید. `docker compose down -v` اجرا نکنید.

## تنظیمات ضروری

- `POSTGRES_PASSWORD` باید دقیقاً رمز فعلی دیتابیس باشد. تغییر فایل env رمز volume موجود را تغییر نمی‌دهد؛ تغییر رمز واقعی باید جداگانه توسط مدیر انجام شود.
- `AUTH_SECRET` باید تصادفی، اختصاصی و حداقل ۳۲ کاراکتر باشد. تغییر آن نشست‌های فعلی را باطل می‌کند.
- `MARKET_SYNC_SECRET` تصادفی و اختصاصی باشد.
- فعلاً `NEXT_PUBLIC_SITE_URL=http://10.64.30.25:8090` و `COOKIE_SECURE=false`. بعد از HTTPS آدرس دامنه را جایگزین و `COOKIE_SECURE=true` کنید و کانتینر را بازسازی کنید.
- `.env`، فایل VPN و توکن‌ها را commit نکنید.

## انتشار

ابتدا روی یک دیتابیس آزمایشی بررسی کنید؛ سپس `docker compose up -d --build` اجرا کنید. migration پیام‌های تماس در راه‌اندازی اعمال می‌شود. volume قبلی آپلود اکنون در `/app/storage` نصب می‌شود تا رسیدها از پوشه public خارج شوند؛ لینک تصاویر تغییر نمی‌کند. پورت PostgreSQL دیگر روی میزبان منتشر نمی‌شود.

Seed رمز ادمین موجود را بازنویسی نمی‌کند؛ برای تغییر عمدی رمز فقط `RESET_ADMIN_PASSWORD=true` به همراه رمز جدید معتبر استفاده کنید. کارت نمونه دیگر ساخته نمی‌شود؛ اطلاعات واقعی کارت را در پنل تنظیم کنید. کارت نمونه موجود را خودتان حذف کنید؛ این نسخه اطلاعات مالی موجود را خودکار تغییر نمی‌دهد.

## نگهداری

هر ۱۰ دقیقه درخواست POST به `/api/maintenance` با هدر `Authorization: Bearer <MARKET_SYNC_SECRET>` ارسال کنید. سفارش‌های پرداخت‌نشده پس از ۲۴ ساعت و بدون رسید در انتظار بررسی لغو و رزروشان آزاد می‌شود. این زمان‌بندی باید روی سرور تنظیم شود؛ داشتن endpoint به‌تنهایی به معنی اجرای خودکار نیست.

پیام‌های تماس در `/admin/messages` دیده می‌شوند. بازیابی رمز پیامکی هنوز غیرفعال است؛ بدون سرویس واقعی SMS نمی‌توان ارسال کد را فعال کرد.

## تست قبل از استفاده واقعی

خرید مهمان و کاربر، تغییر نرخ بازار، خرید هم‌زمان آخرین موجودی، ارسال و رد و ارسال دوباره رسید، تأیید رسید، لغو تکراری سفارش، ارسال سفارش، تنزل نقش ادمین، دریافت غیرمجاز رسید و پایداری فایل‌ها بعد از بازسازی کانتینر را روی دیتابیس آزمایشی بررسی کنید.

## وضعیت بررسی ۱۴ اکتبر ۲۰۲۶

- CI برای commit `c5924e6` موفق بود: بررسی TypeScript، lint، شش تست امنیتی، migration روی PostgreSQL آزمایشی، تست چرخه سفارش و build کامل. تغییرات بعدی باید CI مستقل موفق داشته باشند.
- تست چرخه سفارش جایگزین آزمون end-to-end خرید، کوکی مهمان، آپلود و خرید هم‌زمان نیست.
- audit تولید در این بررسی ۹ هشدار داشت: ۵ high و ۴ moderate، بدون critical. مسیرها شامل PostCSS داخلی Next و وابستگی‌های CLI Prisma (`deepmerge-ts`، `mysql2`، Hono و Valibot) هستند. تعداد هشدار ممکن است با تغییر پایگاه advisory عوض شود.
- فروشگاه از PostgreSQL استفاده می‌کند و سرور dev مربوط به Prisma/Hono را اجرا نمی‌کند؛ بااین‌حال CLI Prisma برای migration در image تولید موجود است. پردازش CSS غیرقابل‌اعتماد توسط کاربر هم قابلیت این فروشگاه نیست. این موارد کاهش سطح مواجهه‌اند، نه اثبات بی‌خطر بودن هشدارها.
- پیشنهاد خودکار audit شامل مهاجرت major به Next 16 و downgrade Prisma به 6 است؛ `npm audit fix --force` اجرا نکنید. ارتقای major یا override باید جداگانه با build، migration و تست سازگاری Docker بررسی شود.
- تنظیمات واقعی، backup قابل‌بازیابی، مالکیت فایل‌های volume قدیمی و زمان‌بندی نگهداری هنوز تأیید نشده‌اند. ورود SSH بدون رمز/کلید در این محیط ممکن نشد؛ هیچ تغییری روی سرور اعمال نشده است.

### بررسی اولیهٔ بدون تغییر روی سرور

پس از ورود با SSH، این دستورات فقط وضعیت غیرمحرمانه را نمایش می‌دهند. خروجی `.env`، `docker inspect` کامل یا `docker compose config` کامل را منتشر نکنید؛ ممکن است رمزها را نمایش دهند.

```bash
cd ~/lafemme-store
git status --short
git log -1 --oneline
docker compose ps
docker compose config --services
docker compose config --volumes
df -h .
docker compose exec -T app id
docker compose exec -T app sh -c 'ls -ld /app/public/uploads /app/storage 2>/dev/null || true'
```

پیش از انتشار، نام واقعی volumeها و دسترسی UID 1001 به فایل‌های موجود را بررسی کنید. build موفق GitHub، سازگاری image و permissionهای volume قدیمی سرور را تضمین نمی‌کند. از اجرای seed عمومی روی دادهٔ واقعی و از تغییر رمز PostgreSQL در `.env` بدون هماهنگی با دیتابیس خودداری کنید.
